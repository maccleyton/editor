## 35.1 Programação Funcional

---

### 35.1.1 Funções como First-class Citizens

- Funções podem ser tratadas como valores.
- Podem ser atribuídas a variáveis, passadas como argumentos e retornadas de outras funções.
- Promove código flexível e reutilizável.

**Exemplo em JavaScript:**

```jsx
const somar = (a, b) => a + b;
const aplicarOperacao = (operacao, x, y) => operacao(x, y);
console.log(aplicarOperacao(somar, 5, 3)); *// Saída: 8*
```

---

### 35.1.2 Imutabilidade

- Valores não podem ser alterados após criação.
- Em vez de modificar dados, cria-se novos objetos com as alterações.
- Facilita raciocínio e evita efeitos colaterais.

**Exemplo em Python:**

```python
numeros = (1, 2, 3)
novos_numeros = tuple(x * 2 for x in numeros)
print(numeros)      *# Saída: (1, 2, 3)*
print(novos_numeros) *# Saída: (2, 4, 6)*
```

---

### 35.1.3 Recursão de Cauda

- Recursão onde a chamada recursiva é a última operação da função.
- Pode ser otimizada pelo compilador para evitar crescimento da pilha.
- Importante para programas funcionais que evitam loops imperativos.

---

### 35.1.4 Higher-Order Functions

- Funções que recebem uma ou mais funções como argumento e/ou retornam uma função.
- Exemplos: map, filter, reduce.
- Facilitam abstração e composição funcional.

---

### 35.1.5 Lazy Evaluation

- Avaliação dos valores só quando necessário.
- Permite definição de estruturas infinitas e melhora desempenho.
- Usado em Haskell e outras linguagens funcionais.

---

### 35.1.6 Pattern Matching

- Técnica para decompor dados e selecionar comportamento baseado na estrutura.
- Simplifica expressões condicionais complexas.

**Exemplo em Haskell:**

```haskell
fatorial 0 = 1
fatorial n = n * fatorial (n - 1)
```

## 35.2 Programação Lógica

---

### 35.2.1 Prolog Básico

- Prolog é linguagem de programação lógica baseada em fatos, regras e consultas.
- Um programa é uma base de conhecimento com cláusulas terminadas em ponto.
- Fatos afirmam informações básicas; regras definem condições para conclusões.
- Variáveis começam com letra maiúscula, átomos com minúscula.
- Consultas interrogam a base para encontrar soluções que satisfazem as condições.

**Exemplo simples de fatos e consulta:**

```prolog
pai(joao, maria).
pai(joao, jose).
mãe(maria, ana).

*% Consulta:*
?- pai(joao, X).
*% Resposta: X = maria ; X = jose.*
```

---

### 35.2.2 Unificação

- Processo básico de correspondência entre termos em Prolog.
- Determina valores para variáveis que tornam duas expressões iguais.
- Fundamental para aplicação de regras e resolução de consultas.

---

### 35.2.3 Backtracking em Prolog

- Técnica que permite explorar alternativas em busca de soluções.
- Quando uma tentativa falha, Prolog volta ao último ponto de decisão e tenta outro caminho.
- Automatiza tentativa e erro estrutural de forma eficiente.

---

### 35.2.4 Cut Operator

- Representado pelo símbolo `!`.
- Controla o backtracking, interrompendo buscas alternativas depois de um ponto.
- Usado para otimizar programas ou implementar escolhas determinísticas.

---

### 35.2.5 Constraint Logic Programming

- Extensão de Prolog que integra programação lógica com resolução de restrições.
- Permite especificar condições (restrições) sobre variáveis (ex.: intervalos numéricos).
- Usada em problemas de otimização, planejamento e scheduling.

---

```prolog
*% Consulta*

```

## 35.3 Programação Concorrente

---

### 35.3.1 Threads e Processos

- **Processos:** instâncias independentes de execução com memória própria.
- **Threads:** fluxos leves dentro de um processo que compartilham memória e recursos.
- Permitem execução paralela e multitarefa, aproveitando múltiplos núcleos e cores do processador.

---

### 35.3.2 Sincronização

- Necessária para controlar acesso concorrente a recursos compartilhados.
- Técnicas comuns: mutex (mutual exclusion), semáforos, barreiras.
- Evita condições de corrida (race conditions) e garante consistência dos dados.

---

### 35.3.3 Deadlock e Starvation

- **Deadlock:** situação onde dois ou mais threads/processos ficam permanentemente bloqueados esperando recursos que uns dos outros possuem.
- **Starvation:** quando um thread/processo nunca é atendido devido a políticas de escalonamento ou competição.
- Detectar e evitar são desafios centrais da programação concorrente.

---

### 35.3.4 Actor Model

- Modelo de concorrência que abstrai entidades como “atores” que trocam mensagens assíncronas.
- Cada ator é independente, mantém estado local e processa mensagens sequencialmente.
- Facilita programação distribuída e paralela, reduzindo problemas tradicionais de sincronização.

---

### 35.3.5 Message Passing (Troca de Mensagens)

- Comunicação entre threads ou processos via envio e recebimento de mensagens.
- Pode ser síncrona (espera pela resposta) ou assíncrona.
- Usado em sistemas distribuídos e linguagens como Erlang.

---

### Exemplo Guiado: Thread simples em Python com sincronização via Lock

```python
import threading

contador = 0
lock = threading.Lock()

def tarefa():
    global contador
    for _ in range(100000):
        with lock:
            contador += 1

threads = []
for _ in range(2):
    t = threading.Thread(target=tarefa)
    threads.append(t)
    t.start()

for t in threads:
    t.join()

print("Valor final do contador:", contador)
```

## 35.4 Programação Reativa

---

### 35.4.1 Observer Pattern Estendido

- Base para programação reativa, permite objetos ("observadores") serem notificados automaticamente de mudanças em outros objetos ("observáveis").
- Estende padrão clássico com suporte à propagação de eventos assíncronos e múltiplos observadores.
- Facilita desacoplamento e facilidade na gestão de mudanças e estados.

---

### 35.4.2 Streams Reativos

- Fluxos contínuos de dados que podem ser produzidos e consumidos assíncronamente.
- Operações como map, filter e reduce podem ser aplicadas nos streams.
- Fundamental para lidar com eventos em tempo real e dados assíncronos.

---

### 35.4.3 Event-Driven Programming

- Paradigma onde o fluxo do programa é controlado por eventos gerados por usuários, sensores, ou outras fontes.
- Programação baseada em callbacks, listeners e handlers.
- Programação reativa amplia este conceito com streams e operadores funcionais.

---

### 35.4.4 Functional Reactive Programming (FRP)

- Combina programação funcional e reativa.
- Usa funções puras e imutabilidade para manipular fluxos de dados e eventos.
- Facilita composição declarativa e reutilização em sistemas reativos.
- Exemplos de frameworks: RxJS, ReactiveX, Elm.

---

### Exemplo Guiado: Observable simples em RxJS (JavaScript)

```jsx
import { Observable } from 'rxjs';

const observable = new Observable(subscriber => {
  subscriber.next('Olá');
  subscriber.next('mundo');
  subscriber.complete();
});

observable.subscribe({
  next(x) { console.log(x); },
  error(err) { console.error('Erro: ' + err); },
  complete() { console.log('Finalizado'); }
});
```
