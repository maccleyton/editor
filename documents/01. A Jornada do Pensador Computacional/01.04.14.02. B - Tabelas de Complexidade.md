## Referência Rápida para Análise de Performance

As tabelas de complexidade fornecem referência essencial para seleção de algoritmos e estruturas de dados baseada em requisitos de performance. Esta seção organiza informações de complexidade temporal e espacial para facilitar tomada de decisões técnicas durante desenvolvimento.

## B.2 Algoritmos de Ordenação

### Algoritmos de Comparação

**Ordenação por Comparação**

| Algoritmo | Melhor Caso | Caso Médio | Pior Caso | Espaço | Estável | In-place |
| --- | --- | --- | --- | --- | --- | --- |
| Bubble Sort | O(n) | O(n²) | O(n²) | O(1) | Sim | Sim |
| Selection Sort | O(n²) | O(n²) | O(n²) | O(1) | Não | Sim |
| Insertion Sort | O(n) | O(n²) | O(n²) | O(1) | Sim | Sim |
| Shell Sort | O(n log n) | O(n^1.5) | O(n²) | O(1) | Não | Sim |
| Merge Sort | O(n log n) | O(n log n) | O(n log n) | O(n) | Sim | Não |
| Quick Sort | O(n log n) | O(n log n) | O(n²) | O(log n) | Não | Sim |
| Heap Sort | O(n log n) | O(n log n) | O(n log n) | O(1) | Não | Sim |
| Tim Sort | O(n) | O(n log n) | O(n log n) | O(n) | Sim | Não |

**Características Importantes:**

- **Estável:** Mantém ordem relativa de elementos iguais
- **In-place:** Requer O(1) espaço adicional
- **Adaptive:** Performance melhora em dados parcialmente ordenados

### Algoritmos Não-Comparativos

**Ordenação sem Comparação**

| Algoritmo | Complexidade Tempo | Complexidade Espaço | Condições |
| --- | --- | --- | --- |
| Counting Sort | O(n + k) | O(k) | Inteiros em range [0, k] |
| Radix Sort | O(d(n + k)) | O(n + k) | Inteiros com d dígitos |
| Bucket Sort | O(n + k) | O(n × k) | Distribuição uniforme |
| Pigeonhole Sort | O(n + k) | O(k) | Range pequeno de valores |

Onde: k = range de valores, d = número de dígitos

**Limites Teóricos:**

- Ordenação por comparação: Ω(n log n) no caso médio
- Ordenação não-comparativa: pode ser O(n) sob certas condições

### Algoritmos Híbridos

**Estratégias Combinadas**

| Algoritmo | Estratégia | Performance | Uso |
| --- | --- | --- | --- |
| Introsort | Quick + Heap + Insertion | O(n log n) garantido | C++ std::sort |

| Dual-Pivot Quicksort | Quicksort modificado | Melhor constante | Java Arrays.sort() |

## Notas sobre Performance

**Fatores que Afetam a Performance Real**

- *Localidade de cache (**Cache locality***): Estruturas contíguas vs. dispersas
- *Previsão de desvios (**Branch prediction***): Código com padrões previsíveis
- *Paralelização (**Parallelization***): Algoritmos que permitem execução concorrente
- **Constantes**: A notação Big O ignora fatores constantes que podem ser significativos
- *Características da entrada (**Input characteristics***): Dados ordenados, distribuição, tamanho real

**Considerações Práticas**

- Para valores pequenos de *n*, algoritmos O(n²) podem ser mais rápidos que O(n log n)
- O overhead de estruturas complexas pode não compensar para conjuntos de dados pequenos
- Algoritmos híbridos frequentemente combinam múltiplas estratégias
- Faça sempre *perfilamento* (***profiling***) com dados reais do seu domínio de aplicação

Esta referência de complexidade serve como guia para seleção inicial de algoritmos, mas testes (***testing***) e perfilamento com dados reais são essenciais para a otimização final de desempenho.
