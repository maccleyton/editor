## 36.1 Árvores Especializadas

---

### 36.1.1 Árvores B e B+

- **Árvore B:**
    - Árvore auto-balanceada de ordem mmm, onde cada nó contém entre $\lceil m/2 \rceil$ e $m$ filhos.
    - Os dados (chaves e valores) ficam armazenados em todos os nós, incluindo internos e folhas.
    - Garantem altura logarítmica e acessos eficientes, muito usadas em bases de dados e sistemas de arquivos.
- **Árvore B+:**
    - Variante da árvore B onde todos os dados são armazenados somente nas folhas.
    - Nós internos armazenam apenas chaves para direcionar buscas.
    - Folhas são conectadas sequencialmente por ponteiros, facilitando varreduras e acessos sequenciais.
    - Mais utilizada em bancos de dados modernos devido à eficiência em leitura sequencial e range queries.

---

### Exemplo guiado conceitual (simplificado):

- Imagine uma árvore B de ordem 3, onde cada nó interno pode ter até 3 filhos.
- Na inserção de chaves, caso um nó estoure o limite, ocorre divisão (split), promovendo uma chave ao pai.
- Em árvore B+, após inserir nas folhas, essas ficam ligadas, permitindo acesso sequencial eficiente.

---

### 36.1.2 Árvores de Segmento

- Árvores usadas para responder rapidamente consultas sobre intervalos em arrays (como soma, máximo).
- Cada nó representa um segmento do array e armazena resultado da operação.
- Permitem atualizações e consultas em $O(\log n)$.

---

### 36.1.3 Árvores de Fenwick (Binary Indexed Trees)

- Estrutura compacta para soma prefixada e atualizações dinâmicas em arrays.
- Mais simples e eficiente em uso de memória que árvores de segmento.
- Operações feitas em $O(\log n)$.

---

### 36.1.4 Tries e Suffix Trees

- **Trie:** árvore na qual cada caminho representa uma string prefixada, usada para dicionários, buscas rápidas e autocomplete.
- **Suffix Tree:** estrutura que armazena todos os sufixos de uma string, útil em buscas de padrões, compressão e bioinformática.

---

### 36.1.5 R-trees (dados espaciais)

- Estrutura para indexação de dados multi-dimensionais, comum em sistemas de informação geográfica e bancos de dados espaciais.
- Armazena retângulos mínimos que cobrem grupos de objetos, facilitando consultas espaciais eficientes.

## 36.2 Heaps e Priority Queues

---

### 36.2.1 Binary Heaps

- Estrutura de dados baseada em árvore binária completa que mantém a propriedade de heap: cada nó é maior (max heap) ou menor (min heap) que os filhos.
- Usada para implementar filas de prioridade eficientes.
- Operações importantes: inserção, remoção do elemento máximo/minimo — ambas em tempo $O(\log n)$.
- Armazenada geralmente em array para eficiência espacial.

---

### Exemplo Simplificado de Binary Min Heap em Python

```python
import heapq

heap = []
*# Inserir elementos*
heapq.heappush(heap, 5)
heapq.heappush(heap, 1)
heapq.heappush(heap, 7)

*# Remover menor elemento*
menor = heapq.heappop(heap)
print(menor)  *# Saída: 1*
```

### 36.2.2 Binomial Heaps

- Conjunto de árvores binomiais que suportam operações rápidas de união.
- Úteis para algoritmos que realizam muitas fusões de filas de prioridade.
- Complexidade amortizada de inserção, união e extração do mínimo é $O(\log n)$.

---

### 36.2.3 Fibonacci Heaps

- Heaps com estrutura mais flexível, melhorando operações de união e diminuição de chave.
- Oferecem operações amortizadas ainda mais rápidas, como inserção e diminuição de chave em $O(1)$.
- Usados em algoritmos avançados (ex.: Dijkstra com heap de Fibonacci).

---

### 36.2.4 Pairing Heaps

- Heaps simples de implementar que possuem boa eficiência prática.
- Operações amortizadas rápidas, especialmente redução de chaves.
- Alternativa popular ao heap de Fibonacci em implementações práticas.

## 36.2 Heaps e Priority Queues

---

### 36.2.1 Binary Heaps

- Estrutura de dados em forma de árvore binária completa, onde cada nó mantém a propriedade de heap (pai é ordenado em relação aos filhos).
- Usada para implementar filas de prioridade que suportam inserção, remoção do menor (ou maior) elemento em tempo $O(\log n)$.
- Frequentemente armazenada em array para eficiência.

---

### Exemplo completo: implementação simples de min binary heap em Java

```java
import java.util.Arrays;

public class BinaryHeap {
    private int[] heap;
    private int size;
    private int capacity;

    public BinaryHeap(int capacity) {
        this.capacity = capacity;
        this.heap = new int[capacity];
        this.size = 0;
    }

    private int parent(int i) { return (i - 1) / 2; }
    private int leftChild(int i) { return 2 * i + 1; }
    private int rightChild(int i) { return 2 * i + 2; }

    private void swap(int i, int j) {
        int temp = heap[i];
        heap[i] = heap[j];
        heap[j] = temp;
    }

    private void resize() {
        capacity *= 2;
        heap = Arrays.copyOf(heap, capacity);
    }

    public void insert(int value) {
        if (size >= capacity) resize();
        heap[size] = value;
        int current = size++;
        while (current > 0 && heap[current] < heap[parent(current)]) {
            swap(current, parent(current));
            current = parent(current);
        }
    }

    private void heapifyDown(int i) {
        int smallest = i;
        int left = leftChild(i);
        int right = rightChild(i);

        if (left < size && heap[left] < heap[smallest]) smallest = left;
        if (right < size && heap[right] < heap[smallest]) smallest = right;

        if (smallest != i) {
            swap(i, smallest);
            heapifyDown(smallest);
        }
    }

    public int extractMin() {
        if (size == 0) throw new RuntimeException("Heap vazio!");
        int min = heap[0];
        heap[0] = heap[--size];
        heapifyDown(0);
        return min;
    }

    public void printHeap() {
        System.out.println(Arrays.toString(Arrays.copyOf(heap, size)));
    }

    public static void main(String[] args) {
        BinaryHeap bh = new BinaryHeap(10);
        bh.insert(10);
        bh.insert(5);
        bh.insert(30);
        bh.insert(3);
        bh.insert(8);

        System.out.println("Heap após inserções:");
        bh.printHeap();

        System.out.println("Elemento mínimo extraído: " + bh.extractMin());
        System.out.println("Heap após extração:");
        bh.printHeap();
    }
}
```

## 36.3 Estruturas para Strings

---

### 36.3.1 Suffix Arrays

- Estrutura que armazena todos os sufixos de uma string em ordem lexicográfica.
- Permite buscas eficientes de padrões e substring em tempo $O(m \log n)$, onde $m$ é tamanho do padrão e $n$ do texto.
- Usados em bioinformática, compressão e buscas rápidas.

---

### 36.3.2 KMP Algorithm (Knuth-Morris-Pratt)

- Algoritmo para buscar padrões em strings com complexidade $O(n+m)$.
- Usa tabela de prefixos para evitar reexame repetido de caracteres.
- Evita retrocessos no texto, melhorando eficiência comparado ao algoritmo ingênuo.

---

### 36.3.3 Rabin-Karp Algorithm

- Usa hashing para encontrar padrões rapidamente.
- Calcula valor hash do padrão e de substrings do texto, comparando hashes para identificar possíveis ocorrências.
- Usa técnica de hash rolante que permite atualizar o hash em tempo constante.

---

**Exemplo básico de Rabin-Karp em Python:**

```python
def rabin_karp(texto, padrao, q=101):
    d = 256  *# base para caracteres ASCII*
    M = len(padrao)
    N = len(texto)
    p = 0  *# hash do padrão*
    t = 0  *# hash da janela atual do texto*
    h = 1

    for i in range(M-1):
        h = (h * d) % q

    for i in range(M):
        p = (d * p + ord(padrao[i])) % q
        t = (d * t + ord(texto[i])) % q

    for i in range(N - M + 1):
        if p == t:
            if texto[i:i+M] == padrao:
                print(f"Encontrado na posição {i}")
        if i < N - M:
            t = (d * (t - ord(texto[i]) * h) + ord(texto[i+M])) % q
            if t < 0:
                t += q

texto = "ABABDABACDABABCABAB"
padrao = "ABABCABAB"
rabin_karp(texto, padrao)
```

### 36.3.4 Aho-Corasick Algorithm

- Algoritmo para busca simultânea de múltiplos padrões em um texto.
- Construção de autômato finito que combina todos os padrões e permite detectar ocorrências em tempo linear do texto.
- Utilizado em filtros de spam, antivírus e pesquisa de palavras-chave.

## 36.4 Estruturas Probabilísticas

---

### 36.4.1 Bloom filters

- Estrutura de dados probabilística para testar se um elemento pertence a um conjunto.
- Usa um vetor de bits e várias funções hash.
- Ao inserir um elemento, marca posições no vetor segundo hashes.
- A consulta retorna "provavelmente presente" ou "definitivamente ausente".
- Possui falso positivo, mas sem falso negativo.
- Usado em sistemas onde espaço e rapidez são críticas, como cache, bancos de dados distribuídos.

**Exemplo básico:**

```python
class BloomFilter:
    def __init__(self, size, hash_count):
        self.size = size
        self.hash_count = hash_count
        self.bit_array = [0] * size

    def _hashes(self, item):
        return [hash(f"{item}{i}") % self.size for i in range(self.hash_count)]

    def add(self, item):
        for h in self._hashes(item):
            self.bit_array[h] = 1

    def check(self, item):
        return all(self.bit_array[h] for h in self._hashes(item))

*# Uso*
bf = BloomFilter(1000, 5)
bf.add("chatgpt")
print(bf.check("chatgpt"))  *# True (provavelmente)*
print(bf.check("openai"))   *# False (definitivamente)*
```

## 36.5 Estruturas Persistentes

---

### 36.5.1 Path Copying

- Técnica para manter versões antigas da estrutura ao modificar dados.
- Ao atualizar, cópia dos nós no caminho da modificação é feita, preservando versões anteriores.
- Suporta fácil acesso às versões antigas sem duplicar toda a estrutura.

---

### 36.5.2 Fat Node Method

- Cada nó armazena múltiplas versões de seus campos juntamente com timestamps.
- Não há cópia de nós, somente anotações de mudanças.
- Consulta retorna valor correto conforme versão desejada.
- Mais eficiente em espaço para estruturas com poucas mudanças.

---

### 36.5.3 Functional Data Structures

- Estruturas imutáveis e persistentes típicas da programação funcional.
- Operações retornam novas versões sem modificar anteriores.
- Exemplos: listas persistentes, árvores persistentemente balanceadas.
- Facilita concorrência e raciocínio matemático.

---

### 36.5.4 Aplicações em Undo/Redo

- Uso clássico é sistemas que permitem desfazer e refazer ações.
- Versões anteriores do estado do sistema são mantidas com estruturas persistentes.
- Permite rápida navegação entre estados sem custo para copiar dados totais.

---

### Exemplo Guiado: Lista Persistente Simples em Python

```python
class Node:
    def __init__(self, val, next_node=None):
        self.val = val
        self.next = next_node

class PersistentList:
    def __init__(self, head=None):
        self.head = head

    def prepend(self, value):
        return PersistentList(Node(value, self.head))

    def to_list(self):
        current = self.head
        result = []
        while current:
            result.append(current.val)
            current = current.next
        return result

plist1 = PersistentList()
plist2 = plist1.prepend(1)
plist3 = plist2.prepend(2)

print(plist1.to_list())  *# []*
print(plist2.to_list())  *# [1]*
print(plist3.to_list())  *# [2, 1]*
```
