### 27.1.1 Abstract Factory

- Fornece uma interface para criar famílias de objetos relacionados sem especificar classes concretas.
- Permite que o sistema seja independente de como seus objetos são criados, compostos e representados.
- Exemplo clássico: criar interfaces gráficas para diferentes sistemas operacionais (Windows, macOS).

Exemplo simplificado em Python:

```python
class BotaoWindows:
    def render(self):
        print("Renderizando botão no estilo Windows")

class BotaoMac:
    def render(self):
        print("Renderizando botão no estilo MacOS")

class UIFactory:
    def criar_botao(self):
        pass

class UIFactoryWindows(UIFactory):
    def criar_botao(self):
        return BotaoWindows()

class UIFactoryMac(UIFactory):
    def criar_botao(self):
        return BotaoMac()

def client(factory: UIFactory):
    botao = factory.criar_botao()
    botao.render()

if __name__ == "__main__":
    client(UIFactoryWindows())  *# Renderizando botão no estilo Windows*
    client(UIFactoryMac())      *# Renderizando botão no estilo MacOS*
```

### 27.1.2 Builder

- Separa a construção de um objeto complexo de sua representação, permitindo criar diferentes representações com o mesmo processo.
- Útil para objetos que exigem passos de construção complexos.

Exemplo simplificado em Python:

```python
class Casa:
    def __init__(self):
        self.janelas = 0
        self.portas = 0
        self.cor = ""

    def __str__(self):
        return f"Casa com {self.janelas} janelas, {self.portas} portas, cor {self.cor}"

class BuilderCasa:
    def __init__(self):
        self.casa = Casa()

    def construir_janelas(self, qtd):
        self.casa.janelas = qtd
        return self

    def construir_portas(self, qtd):
        self.casa.portas = qtd
        return self

    def pintar(self, cor):
        self.casa.cor = cor
        return self

    def construir(self):
        return self.casa

*# Uso*
builder = BuilderCasa()
casa = builder.construir_janelas(4).construir_portas(2).pintar("azul").construir()
print(casa)  *# Casa com 4 janelas, 2 portas, cor azul*
```

### 27.1.3 Prototype

- Permite clonar objetos existentes para criar novos, economizando recursos.
- Útil quando criar um objeto do zero é custoso.

Exemplo em Python:

```python
import copy

class Prototipo:
    def __init__(self, valor):
        self.valor = valor

    def clonar(self):
        return copy.deepcopy(self)

objeto1 = Prototipo([1, 2, 3])
objeto2 = objeto1.clonar()
objeto2.valor.append(4)

print(objeto1.valor)  *# [1, 2, 3]*
print(objeto2.valor)  *# [1, 2, 3, 4]*
```

## 27.2 Padrões Estruturais

---

### 27.2.1 Adapter

- Permite que interfaces incompatíveis trabalhem juntas.
- Converte a interface de uma classe para outra esperada pelo cliente.

---

### 27.2.2 Composite

- Trata objetos individuais e compostos de forma uniforme.
- Facilita o tratamento hierárquico de objetos.

---

### 27.2.3 Decorator

- Permite adicionar funcionalidades a objetos dinamicamente.
- Mantém a interface original, encapsulando funcionalidades extras.

---

### 27.2.4 Facade

- Fornece uma interface simplificada para um conjunto complexo de interfaces.
- Esconde detalhes do subsistema ao cliente.

## 27.3 Padrões Comportamentais

---

### 27.3.1 Command

- Encapsula uma solicitação como um objeto, permitindo parametrizar clientes com diferentes pedidos.
- Facilita desfazer/ refazer operações, filas ou execução agendada.

Exemplo Python:

```python
class Comando:
    def executar(self):
        pass

class AcenderLuz(Comando):
    def executar(self):
        print("Luz acesa")

class ApagarLuz(Comando):
    def executar(self):
        print("Luz apagada")

class ControleRemoto:
    def __init__(self):
        self.comando = None
    def set_comando(self, comando):
        self.comando = comando
    def pressionar_botao(self):
        if self.comando:
            self.comando.executar()

controle = ControleRemoto()
controle.set_comando(AcenderLuz())
controle.pressionar_botao()  *# Luz acesa*
controle.set_comando(ApagarLuz())
controle.pressionar_botao()  *# Luz apagada*
```

### 27.3.2 Iterator

- Permite acessar elementos de uma coleção sequencialmente sem expor sua representação interna.
- Facilita iteração flexível sobre diferentes estruturas de dados.

---

### 27.3.3 Template Method

- Define o esqueleto de um algoritmo em uma operação, deixando passos específicos para subclasses implementarem.
- Promove reutilização e controle do fluxo.

---

### 27.3.4 Visitor

- Permite adicionar novas operações a estruturas de objetos sem modificar as classes.
- Desacopla algoritmo da estrutura de objetos, útil para operações em árvores ou grafos.

---

## 27.4 Anti-patterns

---

### 27.4.1 Identificação

- Anti-pattern é uma solução que parece boa, mas gera problemas como complexidade desnecessária, acoplamento, ou baixa manutenção.
- Exemplos: código espaguete, objetos Deus, repetição de código.

---

### 27.4.2 Refatoração

- Processo de melhorar código sem mudar comportamento.
- Inclui eliminar duplicações, modularizar, simplificar lógica.
- Ajuda a substituir anti-patterns por boas práticas.

---

### 27.4.3 Prevenção

- Codificação orientada a testes (TDD), revisão de código e padrões ajudam a evitar anti-patterns.
- Educação contínua e documentação são essenciais para qualidade.
