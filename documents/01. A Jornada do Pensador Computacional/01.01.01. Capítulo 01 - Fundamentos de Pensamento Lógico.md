## 1.1 O que é Lógica?

Lógica é a ciência que estuda as regras e princípios do raciocínio correto e válido. É essencial para qualquer área que exija decisões fundadas, análises estruturadas ou desenvolvimento de soluções confiáveis, principalmente na computação e engenharia de software.

- **Conceito:** Lógica formaliza o modo como ideias e argumentos são construídos para garantir a verdade das conclusões a partir das premissas.
- **Exemplo prático:** em programação, instruções condicionais (if, else) seguem estruturas lógicas para definir o fluxo do código.

### Exemplo em pseudocódigo:

```bash
Se (idade >= 18) então
    permitir_voto = verdadeiro
Senão
    permitir_voto = falso
Fim Se
```

Esse exemplo usa a lógica condicional para decidir se uma pessoa pode votar.

## 1.2 Pensamento Analítico vs Pensamento Sintético

- **Pensamento Analítico:** dividir um problema em partes menores para entendimento profundo.
    
    Exemplo: ao debugar um programa, o desenvolvedor analisa as funções individualmente para encontrar onde está o erro.
    
- **Pensamento Sintético:** juntar as partes para formar o todo e entender o contexto geral.
    
    Exemplo: após analisar funções, o desenvolvedor junta os resultados para entender o comportamento completo do programa.
    

### Aplicação prática:

Em lógica de programação, primeiro se entende cada função isoladamente (analítico) e depois como interagem para resolver o problema global (sintético).

## 1.3 Resolução de Problemas

Resolver problemas com lógica estruturada envolve uma sequência clara de passos, que guiam do entendimento à solução verificada.

---

### 1.3.1 Identificação do problema

- Definir claramente o problema é o passo mais importante para não resolver algo errado.
- Perguntas chave: o que acontece? Desde quando? Em qual contexto?

### Exemplo prático:

Suponha um programa que não salva dados no banco. A identificação pode ser: “Erro na função de gravação, arquivo corrompido, ou problema de conexão?”

---

### 1.3.2 Decomposição em subproblemas

- Dividir um problema grande em problemas menores e mais manejáveis.
- Isso facilita o desenvolvimento, testes e manutenção.

### Exemplo prático em pseudocódigo para salvar dados:

```bash
Função salvarDados(dados):
    conectarBanco()
    validarDados(dados)
    gravarDados(dados)
    desconectarBanco()
Fim Função
```

Aqui o problema “salvar dados” foi dividido em 4 subproblemas menores.

---

### 1.3.3 Estratégias de solução

- **Tentativa e erro:** testar hipóteses e observar resultados.
- **Algoritmos:** uso de passos claros e repetitivos, como ordenar listas, buscar elementos, etc.
- **Heurísticas:** regras práticas como “se não encontrar, dividir problema ao meio” (exemplo: busca binária).
- **Algoritmos recursivos:** resolver subproblemas repetidos em menor escala.

### Exemplo: Busca sequencial vs busca binária (pseudocódigo)

Busca sequencial:

```bash
Para cada elemento em lista:
    Se elemento == busca então
        retornar posição
Fim Para
Retornar -1  // não encontrado
```

Busca binária (lista ordenada):

```bash
inicio = 0
fim = tamanho(lista) - 1
Enquanto inicio <= fim:
    meio = (inicio + fim) / 2
    Se lista[meio] == busca então
        retornar meio
    Se lista[meio] < busca então
        inicio = meio + 1
    Senão
        fim = meio - 1
Retornar -1  // não encontrado
```

---

### 1.3.4 Validação e verificação

- **Validação:** verificar se a solução atende realmente o problema inicial.
    
    Exemplo: após implementar o algoritmo, testar se ele retorna o resultado esperado para vários dados.
    
- **Verificação:** garantir que o algoritmo está correto em cada passo, sem erros de programação.
    
    Exemplo: depurar o código ou realizar testes unitários para verificar cada função.
    

---

### Exercícios Comentados

1. **Identificação do problema**
    
    Problema: “Um site web está carregando muito lentamente”.
    
    Comentário: identificar possíveis causas (servidor instável, imagens muito pesadas, consultas ao banco lentas).
    
2. **Decomposição em subproblemas**
    
    Problema: “Registrar usuário em uma plataforma online”.
    
    Exemplo de decomposição: entrada de dados → validação → armazenar no banco → enviar confirmação por email.
    
3. **Escolher estratégia de solução**
    
    Problema: “Encontrar o maior número em uma lista não ordenada”.
    
    Solução possível: percorrer toda a lista comparando elemento a elemento (busca linear).
    
4. **Validação e verificação**
    
    Questão: “Depois de implementar, como garantir que o código funciona?”
    
    Sugestão: escrever testes automáticos que simulam várias entradas e verificam se o resultado é o esperado.

## 1.4 Abstração

A abstração é um conceito-chave no pensamento lógico e computacional, pois permite simplificar problemas complexos ao focar nos aspectos mais importantes, ignorando detalhes menos relevantes.

---

### 1.4.1 Níveis de abstração

Níveis de abstração se referem a diferentes graus de detalhamento com que um sistema, problema ou conceito é representado:

- **Alto nível (mais abstrato):** visão geral, simplificada, foco em funcionalidades e comportamentos básicos.
    
    Exemplo: pensar em um carro como “algo que transporta pessoas”, sem detalhar motor, pneus ou sistema elétrico.
    
- **Nível médio:** detalha algumas partes importantes, mas ainda não entra em detalhes técnicos minuciosos.
    
    Exemplo: saber que o carro tem motor, transmissão, suspensão, mas sem entrar fundo em cada componente.
    
- **Baixo nível (mais detalhado):** especificação detalhada de cada componente e suas interações.
    
    Exemplo: projeto elétrico do motor, programação dos sensores, descrição exata das ligações.
    

No desenvolvimento de software, níveis de abstração ajudam a definir desde o escopo do sistema até o código específico.

---

### 1.4.2 Modelagem de problemas

Modelagem é representar o problema ou sistema usando conceitos como diagramas, fluxos, pseudocódigo ou estruturas de dados, facilitando sua compreensão e solução.

- Modelos abstraem características essenciais do problema.
- Ferramentas comuns: diagramas UML, fluxogramas, diagramas de classe, pseudocódigo.

Exemplo prático: para um sistema de cadastro, usa-se um diagrama de classes para representar entidades (Usuário, Produto, Pedido) e suas relações.

---

### 1.4.3 Padrões e generalização

Padrões são soluções reutilizáveis para problemas comuns. Generalização é criar uma abstração que engloba várias situações específicas para tornar o código ou modelo mais flexível.

- **Padrões de projeto (design patterns):** como Singleton, Observer, Factory, que resolvem problemas típicos em desenvolvimento de software.
- Generalização permite criar funções/métodos que funcionam para vários casos, usando parâmetros ou tipos genéricos.

Exemplo:

Um método genérico de ordenação que pode ordenar listas de números, strings ou objetos, desde que seja definido como comparar os elementos.

## 1.5 Pensamento Computacional

Pensamento computacional é um conjunto de habilidades para resolver problemas de forma sistemática e eficiente, inspirado na lógica e processos usados em computação.

---

### 1.5.1 Decomposição

Consiste em dividir um problema complexo em partes menores e mais simples para facilitar o entendimento e a solução.

Exemplo: para criar um jogo, dividir em subproblemas como controles do jogador, movimento dos inimigos, pontuação e interface gráfica.

---

### 1.5.2 Reconhecimento de padrões

Identificar semelhanças, repetições e regularidades no problema ou dados para facilitar sua solução.

Exemplo: reconhecer que vários problemas envolvem buscas em listas ordenadas, o que pode usar um algoritmo binário.

---

### 1.5.3 Abstração

Focar nos detalhes mais importantes do problema enquanto ignora aspectos menos relevantes, para simplificar.

Exemplo: ao simular uma cidade, abstrair carros, comportamentos de trânsito e rotas, sem detalhar cada pessoa na cidade.

---

### 1.5.4 Algoritmos

Sequências passo a passo de instruções para resolver problemas. Algoritmos são a base do pensamento computacional.

Exemplo simples: algoritmo para calcular a soma de números em uma lista.

Pseudocódigo:

```bash
soma = 0
Para cada numero em lista:
    soma = soma + numero
Retornar soma
```
