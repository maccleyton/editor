## 32.1 Metodologias de Resolução

---

### 32.1.1 Polya’s Problem-Solving Method

George Polya propôs uma metodologia estruturada para resolver problemas, composta por quatro etapas principais:

1. **Compreender o problema:**
    - Leia atentamente e certifique-se de entender o que é pedido.
    - Identifique dados importantes e o que é desconhecido.
    - Reescreva o problema com suas próprias palavras.
    - Se necessário, desenhe diagramas ou tabelas para auxiliar a visualização.
2. **Elaborar um plano:**
    - Considere estratégias para resolver, como dividir o problema, trabalhar com casos mais simples, buscar padrões.
    - Pense em métodos semelhantes usados anteriormente.
    - Escolha a abordagem mais promissora.
3. **Executar o plano:**
    - Aplique o plano passo a passo com cuidado e paciência.
    - Documente cada etapa para facilitar revisão.
4. **Rever e analisar:**
    - Verifique se o resultado está correto e faz sentido.
    - Reflita sobre o processo e veja se a solução pode ser generalizada ou simplificada.
    - Considere outras formas de resolver o problema.

---

### Exemplo Guiado: Problema dos Cumprimentos

**Problema:** Em uma festa, 10 pessoas cumprimentam-se todas uma vez. Quantos cumprimentos são feitos?

**Passos Polya:**

1. Compreender: Cada pessoa cumprimenta as outras 9 pessoas.
2. Plano: Multiplica-se número de pessoas pelo número de cumprimentos por pessoa.
3. Execução: $10 \times 9 = 90$.
4. Revisão: Cada cumprimento é contado duas vezes (A cumprimenta B e B cumprimenta A). Então o total final é $90/2 = 45$.

### 32.1.2 Divide and Conquer

- Método que divide um problema em subproblemas menores, resolve-os e combina soluções.
- Algoritmos clássicos: merge sort, quick sort e busca binária.
- Reduz complexidade e facilita paralelismo.

---

### 32.1.3 Tentativa e Erro Estruturada

- Abordagem sistemática de tentar soluções e retroceder (backtracking) se não funcionar.
- Útil em problemas com grandes espaços de soluções, como puzzles, jogos e programação.

---

### 32.1.4 Analogia e Generalização

- Resolver problemas relacionando-os a problemas já conhecidos.
- Generalizar soluções para aplicar em situações similares.
- Exemplo: Usar solução de problema matemático clássico para problema prático correlato.

## 32.2 Problemas NP e Complexidade

---

### 32.2.1 Classes P e NP

- **Classe P:** Problemas que podem ser resolvidos em tempo polinomial por um algoritmo determinístico.
- **Classe NP:** Problemas para os quais uma solução proposta pode ser verificada em tempo polinomial.
- A grande questão da ciência da computação é se P = NP, ou seja, se todo problema cuja solução pode ser verificada rapidamente também pode ser resolvido rapidamente.

---

### 32.2.2 Problemas NP-completos

- São os problemas mais difíceis em NP, para os quais qualquer problema em NP pode ser reduzido em tempo polinomial a eles.
- Exemplos clássicos:
    - Problema do Caixeiro Viajante (TSP)
    - Problema da Mochila (Knapsack)
    - Problema do Clique
    - Problema do Ciclo Hamiltoniano
    - Problema de Satisfatibilidade Booleana (SAT)
- Resolver um problema NP-completo eficientemente significaria resolver todos os problemas NP eficientemente.

---

### 32.2.3 Heurísticas e Aproximações

- Devido à dificuldade dos NP-completos, usa-se heurísticas que não garantem encontrar a solução ótima, mas que normalmente encontram soluções boas em tempo razoável.
- Exemplos: algoritmos gulosos, algoritmos genéticos, algoritmos de aproximação.
- Técnicas balanceiam qualidade de solução e eficiência.

---

### 32.2.4 Redução de Problemas

- Técnica para mostrar que resolver um problema é tão difícil quanto outro já conhecido.
- Utilizada para classificar problemas quanto à sua complexidade.
- Reduz-se problema A a problema B em tempo polinomial; se B é solucionável eficientemente, A também pode ser.

---

### Exemplo Prático: Problema da Mochila via Programação Dinâmica

```python
def mochila(pesos, valores, capacidade):
    n = len(pesos)
    dp = [[0]*(capacidade+1) for _ in range(n+1)]

    for i in range(1, n+1):
        for w in range(capacidade+1):
            if pesos[i-1] <= w:
                dp[i][w] = max(valores[i-1] + dp[i-1][w - pesos[i-1]], dp[i-1][w])
            else:
                dp[i][w] = dp[i-1][w]

    return dp[n][capacidade]

pesos = [1, 3, 4, 5]
valores = [1, 4, 5, 7]
capacidade = 7

print("Valor máximo na mochila:", mochila(pesos, valores, capacidade))
```

### 32.3.1 Problema do Caixeiro Viajante (TSP)

- Consiste em encontrar o menor caminho que passa por todas as cidades de uma lista exatamente uma vez e retorna à cidade inicial.
- Problema NP-difícil, complexidade crescente fatorial para tamanho nnn.
- Métodos exatos: força bruta, programação dinâmica Held-Karp (tempo exponencial).
- Métodos heurísticos: algoritmo do vizinho mais próximo, algoritmos genéticos, simulated annealing.

---

### Exemplo simples do algoritmo do vizinho mais próximo em Python

```python
import math

def distancia(p1, p2):
    return math.sqrt((p1[0]-p2[0])**2 + (p1[1]-p2[1])**2)

def vizinho_mais_proximo(cidades):
    visitado = [0]
    while len(visitado) < len(cidades):
        ultimo = visitado[-1]
        n_proximo = min(
            [i for i in range(len(cidades)) if i not in visitado],
            key=lambda x: distancia(cidades[ultimo], cidades[x])
        )
        visitado.append(n_proximo)
    return visitado

cidades = [(0,0),(1,3),(4,3),(6,1),(3,0)]
rota = vizinho_mais_proximo(cidades)
print("Rota:", rota)
```

## 32.4 Estratégias de Otimização

---

### 32.4.1 Aproximação vs Solução Exata

- **Soluções exatas** garantem encontrar a melhor resposta, mas podem ser computacionalmente inviáveis para problemas complexos (ex.: NP-completos).
- **Soluções aproximadas** oferecem respostas boas em tempo mais rápido, explorando heurísticas e algoritmos de aproximação.
- Escolher depende do contexto, necessidade de precisão e recursos disponíveis.

---

### 32.4.2 Trade-offs Tempo vs Precisão

- Em muitos casos, melhorar a precisão do resultado exige mais tempo de processamento.
- Exemplo clássico: algoritmos de machine learning que aumentam o tempo para ajustes finos do modelo.
- O trade-off deve ser gerenciado considerando custo computacional, deadline e qualidade desejada.

---

### 32.4.3 Paralelização de Algoritmos

- Dividir a carga de trabalho em diversas unidades para acelerar computação.
- Exemplo: paralelismo em algoritmos de ordenação, busca e otimização.
- Necessita cuidado com sincronização e balanceamento de carga para evitar overheads.

---

### 32.4.4 Cache-Friendly Algorithms

- Algoritmos projetados para melhorar o uso eficiente das memórias cache do processador.
- Minimizar falhas de cache melhora desempenho e reduz latência.
- Técnicas incluem acesso sequencial, blocos e otimização espacial e temporal.

---

### Exemplo Guiado: Trade-off Entre Tempo e Precisão em Aproximação de Funções

```python
import time
import numpy as np
from scipy.integrate import quad

def funcao(x):
    return np.exp(-x**2)

*# Cálculo exato com scipy*
inicio = time.time()
area_exata, _ = quad(funcao, 0, 1)
fim = time.time()
print(f"Exato: {area_exata:.6f} em {fim-inicio:.6f} segundos")

*# Aproximação simples com somatório Riemann*
inicio = time.time()
n = 10000
x = np.linspace(0, 1, n)
dx = 1/n
area_approx = np.sum(funcao(x)) * dx
fim = time.time()
print(f"Aproximado: {area_approx:.6f} em {fim-inicio:.6f} segundos")
```
